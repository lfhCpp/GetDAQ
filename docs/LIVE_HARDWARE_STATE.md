# 固定硬件控制位的实际只读观察

本功能用于配置维护和恢复前核对。Qt操作台只发送认证GET请求，原生ECC后端通过现有板端Ice接口检查元数据，再读取固定控制位。它不是“恢复成功”按钮，不改变ECC/Run状态，不读取DAQ数据缓冲区或任意地址。

## 1. 能读取什么

| 板卡 | 固定设备/寄存器 | 固定字段 |
| --- | --- | --- |
| CoBo | ctrl / pipeCtrl | firmwareEnable、intEnable |
| CoBo | ctrl / mutantConfig | initDone、mutantMode |
| MuTaNT | CARD_B_EMC / TRIGGER_CTRL | run |

字段沿用已有主机停止/描述核对流程使用的控制状态位。返回值必须为0或1。未完成名字、设备清单、元数据/本地权限及全部固定字段核对的节点只返回unavailable，不保留部分读取值。

没有“输入任意寄存器地址”功能，也没有写入、DAQ Stop、Reset或接收器操作。新版主机仍使用原板端部署，本功能没有重构getHwServer或IceEirfu。

## 2. 在操作台使用

1. 打开 **Live hardware control bits...** 菜单。Native客户端的地址、端口、凭据路径、service ID和snapshot摘要会预填；也可明确填写另一个要观察的服务。
2. 凭据填写操作台本地文件路径，不填写令牌明文。使用现有ECC服务的Bearer凭据。
3. 点击 **Inspect fixed hardware bits once**。窗口先GET身份，核对预期service ID和snapshot，再GET硬件观察，核对同一实例、参数及工件摘要。
4. 查看每个节点的实际字段或unavailable原因。父ECC如果仍UNKNOWN/需要核对，窗口明确保持提示；不会因所有读取为0就解除门槛。
5. 每次刷新由用户明确点击，没有自动轮询硬件。接收观察超过六秒后撤回表内值，需再次明确检查。地址、端口、凭据或选择摘要变化会取消旧请求并撤回旧值。

六秒是客户端接收后的显示有效期，不是现场硬实时保证。表格的Sample time (Unix ms)列显示节点完成读取时的Unix毫秒时间戳（自1970年UTC零点起的毫秒数），失败节点留空；可与主机时间核对。节点采样时间和父操作绑定也保存在JSON；多节点读取不是一个物理时刻的原子快照。

## 3. API与后端执行

观察前后重新核对服务启动时绑定的外部配置/描述/工件来源；变动时返回503，客户端撤回整批值，恢复原字节也不能清除该实例的固定输入故障。这个检查不读取并发写入的操作日志容器，也不持控制命令锁。

现有ECC服务提供认证 `GET /v1/hardware-state`，无请求体和任意寄存器参数。返回kind为 `getdaq.hardware-state-observation`，绑定服务实例、父snapshot、configuration/artifact摘要、父状态和原操作ID。

每节点记录包括角色、available、诊断、采样Unix毫秒及values。失败节点values为空、采样时间为0。客户端便携C++11解码器限制1MiB/195节点，拒绝重复节点、未知字段、超范围位值及错误的恢复/加载/全局控制声明。

输出始终保持：

```json
"recovery_verified": false,
"actual_loaded_configuration_verified": false,
"global_control_verified": false
```

`busy`表示捕获时已有ECC动作；该批不进行硬件RPC。`consistent`只说明观察期间没有检测到本机协调器动作/父状态代次变化，不证明其他主机、硬件自身或所有节点在同一个物理时刻保持不变。发生本机动作变化时撤回整批采样。

查询在Qt线程池中执行，HTTP事件线程不等待板端读取。同一来源/硬件观察入口一次只允许一项，不排队。原生代码仅短暂捕获/核对命令代次，不持有命令锁执行硬件RPC或完整文件核对，因此不会把慢板端查询当成阻塞停采的长期控制锁。

默认总预算2000ms，节点连接/调用超时最多300ms，调用之间检查预算；一些高层元数据/读取方法内部有多次RPC，以及本地解析、调度和销毁开销，不能据此宣称两秒硬截止。窗口请求超时、错误或身份不符时撤回值，不安排控制动作。

## 4. 为什么它不直接解除UNKNOWN

当前普通TCP/FDT旧发送器接口没有远端状态能力。本地主机DataSenderClient的Fresh不是“旧发送器一定停止”的证明；读取上述控制位也不能证明发送器连接、所有接收会话、整个准备/校准流程或真实当前配置已加载。

新主机同机地址占用保护也不是板端全局/跨主机独占锁。控制位为0只能作为本次读取的负向状态信息，不能覆盖其他未核对条件。完整Reconcile仍需独立硬件、加载、发送器和数据会话核对，现有后端默认拒绝缺少验证的恢复。

这个观察接口补充维护信息与恢复核对依据，不把采样、配置文件恢复、原Run关系恢复或历史Configure应答当作完整系统恢复。

## 5. 验证范围

普通原生控制器在实际Ice回环夹具中验证两种编码、完整CoBo/MuTaNT字段、节点名字不符拒绝、忙碌查询无硬件动作及零写入；新增真实Ice字段RPC受控等待时，负向请求仍取得协调器锁并按原门槛拒绝，父状态/ID不变，但动作代次使整批读取撤回。该测试验证锁与过期观察，不声称实际停采成功；独立ECC服务的认证HTTP两编码验证身份/摘要、错误凭据401、元数据不符撤回与父缓存不变。

Qt生产窗口使用实际本地HTTP测试服务器验证认证GET-only、UNKNOWN保持、错误/配置改变撤回和无自动请求；这是窗口协议测试，不替代该窗口到现场板端的完整链路。最终内存检查、窗口总计、交付输入与未验范围以[验证记录](VALIDATION.md)第70.29节为准。现场固件、真实停止、持续性能和目标平台验收仍须独立完成。
