1 运行原理与总览

GetDAQ

安装、配置与采集操作指南

适用：原版 SOAP ECC + DataExporter / DataRouter；2026-11-22。

1 运行原理

GetDAQ 是操作界面；getEccSoapServer 负责给板卡发命令；DataExporter / DataRouter 负责收数据、写磁盘。原始数据不经过 GUI、ECC 或配置分发服务。

GetDAQ → SOAP ECC → CoBo / AsAd / AGET
CoBo → DataExporter / DataRouter → raw data
Sentry / node agent: monitoring and management

程序职责



程序职责
GetDAQ连接多个 ECC、采集操作、状态显示及本地运行记录。
getEccSoapServer原版 SOAP ECC；Describe、Prepare、Configure、Start、Stop。
DataExporter原版数据接收和 FrameStorage；另提供 TCP 导出供在线波形预览。
DataRouter可选原版接收器；也兼容其他主机已有的外部 DataRouter。
getdaq-sentry文件计数、磁盘、吞吐统计与 catalog 归档。
Node agent / 配置服务主从配对、整目录分发、缓存、独立后台实例管理。
getdaq-control-mcpAI 客户端的独立 stdio 接口，复用 GUI YAML 和 SOAP / Sentry 客户端。


最短操作顺序

安装 → 确定目录 → 填 IP、端口和实验 ID → 启动服务或选择已有服务 → Connect → Progress 至 Ready → Run start → Run stop。

ECC、接收器、GUI 可以同机或分布在多台电脑。多实例指多套后台，不要求多开主界面。

本文覆盖

Configuration → User guide 可在软件内选择中文或英文；支持章节导航、搜索和 Save PDF 导出，离线可读。

第 2 页：Ubuntu 安装；第 3 页：macOS 与 IP / 端口；第 4 页：单机设置； 第 5 页：主从与文件同步；第 6 页：采集与日志；第 7 页：离线 / 在线 / 3D 波形；第 8 页：MCP 与排错。第 9--20 页逐项解释界面按钮与配置字段，其中第 11--18 页集中说明配置。
GET、Ice、Boost、CompoundConfig、gSOAP、MFM 等必需源码已内置。仍需基础编译工具和 Qt 5；不是“无需任何系统依赖”。历史 source/ 不参与构建。

2 Ubuntu 安装教程

建议在目标 Ubuntu 本机编译，安装到一个新的目录，保留旧版和用户数据。

第一步：安装基础工具

使用具有 sudo 权限的账户，在 Ubuntu 终端执行： 
sudo apt update
sudo apt install -y build-essential cmake python3 git openssl \
  qtbase5-dev libqt5svg5-dev qttools5-dev-tools
qmake -v
qmake -v 应显示 Qt 5。机器装有多套 Qt 时，在构建参数中用 --qmake /path/to/qmake 指定 Qt 5。完整构建不需要另装旧 GET / Boost / Ice，也不必安装 ROOT。

第二步：获取完整项目源码

已有完整源码目录就直接进入，不要只拷贝某一个程序。 
git clone https://github.com/lfhCpp/GetDAQ.git
cd GetDAQ
python3 tools/verify-product-boundary.py
python3 tools/verify-original-backends.py
若复制的是已有安装包、源码位于 code/，先 cd code 再执行构建命令。

第三步：编译并安装到新目录

以下 dist-linux 必须尚不存在；再次构建可换新名称。 
python3 tools/build-suite.py --profile full --jobs 2 \
  --stage "$PWD/dist-linux"
python3 tools/build-suite.py --verify-stage "$PWD/dist-linux"
./dist-linux/bin/GetDAQ
编译成功后，dist-linux/bin/ 包含主程序、原版后台、配置编辑器、波形查看器和 MCP； 资源在 share/，说明书在 docs/。完整构建包含 16 个程序。

内存较小可把 --jobs 2 改为 --jobs 1；只需要连接外部 ECC 可选 --profile control，不包含本机整套后台。

已有现场安装怎样启动或升级

若安装目录已经有 start-getdaq.sh，可使用它；普通源码 / 新 stage 不保证有该脚本，直接运行 bin/GetDAQ 即可。 复制同平台运行包时，整体保留 bin/、share/ 和 docs/；目标机仍需匹配的 Qt / 系统运行库。

升级使用新的运行目录。不要清空配置、原始数据、运行记录或主从配对缓存；不在采集期间强制杀后台。
首次打开不会自动复位或启动板卡。先完成第 4 / 5 页的路径与网络设置，再明确启动后台或连接已有 ECC。

3 macOS 与网络地址

Ubuntu 可执行文件不能直接在 Mac 上运行，需在 Mac 本机编译。

macOS 安装步骤

安装 Xcode 命令行工具、Python 3、CMake 和匹配 CPU 架构的 Qt 5。已有 Homebrew 可使用： 
xcode-select --install
brew install cmake qt@5
cd /Users/attpc/Documents/GetDAQ
./build-macos.command --jobs 2
也可使用已有 Qt 5.15 kit：--qmake /path/to/Qt5/bin/qmake。 构建后打开 dist-macos/GetDAQ.app。重复打包选新目录，例如 --output dist-macos-new。详细步骤见 docs/MACOS_INSTALL.md。

macOS 已有适配入口，原生构建及实板验收尚未完成。不要复制 Ubuntu 的绝对路径、配对缓存或网络设置当作 Mac 的有效配置。

4 单机配置教程

先选目录，再确认本机网卡，最后填实验 ID 和启动服务。

第一步：明确三个目录



目录示例与含义
Configuration source主控安装目录 config/。放整套实验 XML/XCFG、拓扑和引用资源。
Project data folder默认 /home/user/GetDAQ/data。ECC、接收器、Sentry 在此工作，配置复制到此，原始 .graw 也写在此。
GUI Run records root默认 /home/user/GetDAQ/runs。GUI YAML、journal、备份和元信息；不是原始数据目录。


新配置、项目、日志和缓存默认放在 Home 下可见的 GetDAQ 目录。已有项目沿用保存路径；安装目录没有 config 时，配置源默认 Home/GetDAQ/config。

从哪启动接收器决定其工作目录。受管模式会明确设置 Project data folder，不依赖打开 GUI 时终端所在目录。

第二步：启动新的原版后台

  1. 在 Nodes / Paths 右侧的 Master / Slave 选择 Master，进入 Create ECC / data services。
  2. 首次使用点 Use this computer (automatic)，添加执行主机。
  3. 点 Add boards / ECC…，选择 Configuration source、Experiment ID，并指定 ECC host / Data receiver host 及该主机的 Project data folder。
  4. 填接收电脑的 Control IP、Data IP、Router control/data 端口、ECC SOAP 端口；核对 AsAd、AGET 和 CoBo 拓扑文件。
  5. 保留 Sync configuration to project folders，点击 Start project services。软件先分发配置，再在项目目录启动原版后台和共享 Sentry。
下面只是对应关系示意，受管模式会生成实际参数： 
cd /home/user/DAQ/experiment-data
dataRouter 192.168.40.10 192.168.50.10 TCP FrameStorage
getEccSoapServer --port 8083 --alarm-port 46011 \
  --config-repo-url /home/user/DAQ/experiment-data
不要在同端口再手工启动第二套程序。DataExporter 的受管入口使用生成的控制 / 数据端口参数和实例文件，状态以实例管理显示的实际命令为准。

已有 ECC / DataRouter：不必重建后台

选择 Connect existing ECC，填写实际 SOAP ECC host / port，检查连接后保存使用； Router host 填接收数据网卡，Router port 填数据端口，Sentry 填对应目录的监控服务。 外部 DataRouter 不需要另起 DataExporter；已有 NFS / ECC 仓库继续使用原配置。
旧 ECC 准备成功不证明数据接收目标一定正确。先核对 Router 数据端口与地址，再看实际文件是否增长。

5 主从机、配置 ID 与同步

从机选择自己的目录；实验配置只在主控维护。

从控 Slave 的设置

  1. 选择 Slave，设置本机 Configuration cache 与 Project data folder。前者是软件缓存；后者是后台工作目录和原始数据目录。
  2. 点击 Enable / check slave，软件启用节点管理服务。
  3. 点 Copy pairing code，到主控的 Add slave 粘贴。邀请码有有效期，配对后即消费，不需反复复制。
  4. 主控不可达时保留配对。需要更换主控，用 Remove master connection… 明确确认；旧管理凭据失效，后台、数据和审计记录保留。

主控 Master 的设置

添加从机后，创建板卡组时选择 ECC host、Data receiver host；同一组的两类服务可以在不同电脑。 各执行电脑使用本机 Project data folder，不能把主机绝对路径直接当作从机目录。 同机多开后台时，以主机、组名称、端口和实例身份区分，不共享同一块板卡的控制权。 首次设置默认展开。在 ECC and boards 表中用 Ctrl / Shift 多选组，点 Start selected groups and use；只启动所选组，并自动带入 Run Setup 连接查询，不启动采集。各 ECC 的 CoBo 索引独立保留。从机的 Remove selected inactive entry 仅隐藏无进程的历史项，保留数据与审计。

配置文件从哪里来、到哪里去

主控 Configuration source 整目录 → 不可变配置版本 → 本机 / 从机缓存 → 该执行主机的 Project data folder。资源保持相对路径；原始数据不随配置分发传输。


GUI 字段 / 操作原版 ECC 匹配的文件名（.xcfg 或 .xml）
Describe ID = cobo0describe-cobo0
Prepare ID = pedestalsconfigure-pedestals，不是 prepare-pedestals
Configure ID = pedestalsconfigure-pedestals
ExperimentRun 名称及缺省 ID；节点明确填写的 ID 优先。


修改配置以后

  1. 用原版配置编辑器保存到 Configuration source。
  2. Tools → Sync project configuration…，选择本机、指定从机或全部执行主机。
  3. 活动实例需确认警告；稳定 Ready / Running 也可同步，不强制退回 Idle。已观察到硬件命令仍在转换时暂缓替换文件，未知状态需明确确认。
  4. 同步只改变磁盘文件。板卡仍用上次加载的参数；通过相应 ECC Configure 才更新硬件。
已保存连接可用 Remove saved connection 从历史列表移除。路径摘要即时显示当前设置，旧运行目录另列提示，正常重启后台后应用新工作目录。Nodes / Paths 的 Save and apply 主要保存连接 YAML，不等于立刻发布 XML/XCFG。 后台启动和项目发布也会检查源目录；外部未托管 ECC 的 NFS / 仓库不被擅自覆盖。 被替换配置保存在项目目录的备份中，不删除原始数据。

6 开始、停止与日志

以 ECC 实际状态判断采集；以接收目录判断写盘。

开始采集

  1. Run setup 核对 Experiment、Run 编号，Save YAML 保存本次连接设置。
  2. Connect 查询真实状态。若已经 Ready，可直接开始；不必因为重连再强制回到 Idle。
  3. 初次初始化，用 Progress all 或选定节点 Progress，依次 Describe、Prepare、Configure；MuTaNT / CoBo 顺序由界面流程协调。
  4. Ready 后 Run start，观察 Running、Files / Data GB、数据率和磁盘空间。
  5. 核对接收主机项目目录里的 .graw 是否持续增长，必要时查看在线波形。

停止采集

点 Run stop，先等待所有参与 ECC 真实返回 Ready。之后是 Sentry catalog、配置备份与本地记录。 记录失败不等于硬件未停止；也不能仅凭本地日志断言板卡已停。

归档成功通常在项目目录 <Experiment>/run_NNNN/；归档警告时数据可能仍在原目录，以实际文件和日志为准。

警告不再锁死操作



情况行为
本地记录 / 备份失败告警并保留已有记录，可手动开始下一次；不伪称已成功保存，自动续跑取消。
catalog 结果不确定保留未知回执，不自动重试；确认 Ready 后允许关闭本地 Run 并继续手动操作。
状态过期、监控缺失需要确认时弹出警告；硬件命令仍由 ECC 判断。
Start / Stop / Disconnect连接后保持可用；正在执行的硬件命令串行处理，Stop 可排在当前命令后。
已有同号 Run / 接收文件明确询问后才保留或替换记录；不直接删除原始数据。


Start 观察到已经 Running 时只附着观察，不再重复 Start；停止外部开始的采集也可用 Stop。 断开可在确认后脱离未完成工作，不停止远端采集。

查看、清屏和导出日志

原 Event log 区域切换 Event log / ECC log / DataExporter log / DataRouter log，右侧选择主机和实例；也可选择共享 Sentry。 每次重新打开 GUI，新日志会话从空白开始，不加载之前的输出；首次附着后台日志后只收集新内容。Data log 右侧 Clear 清显示，导出仅含本次会话。 Tools → Logs → Export combined logs… 导出 TXT，按 GUI 接收时间与顺序号合并，分隔来源；远端原文时间保留，不能冒充完全同步的跨主机事件时钟。
关闭 GUI、Disconnect、Stop acquisition、Stop backend services 是四件事。需要关闭后台时使用实例管理，并先核对采集状态。

7 波形查看与 3D

在线、离线使用相同的电子学通道和绘图方式，没有 pad 映射。

离线：读已有 .graw / .gmat

Tools 中打开波形查看器，Open waveform 选文件；用 Event ID / Go to event 选事件，Frame 选该事件的帧，AGET 选芯片，Channels… 勾选通道。 .gmat 没有真实事件号，用帧号选择。PNG / CSV 从 Export plot/data… 导出。

在线：独立连接 DataExporter

Tools → Online waveform viewer…。直接从 DataExporter 选择框选择当前配置中的实例或全部实例，软件自动使用受管项目的导出地址，不再手填 IP。外部接收器在连接配置中选择 DataExporter 和预览端口（常见 46491），也可在 Nodes / Paths 设置 Preview host / Preview TCP port。选择后自动连接，再选 Source、CoBo、AsAd、AGET 与通道。

Follow latest 跟随最新事件；取消后选缓存事件或用 Event ID / Go。Cache 限 100 事件 / 4096 帧 / 256 MiB 并自动淘汰；Received total 仅累计计数，不保留等量数据。 预览允许丢帧，正常落盘优先。关闭查看器不停止后台。 旧 DataRouter 必须确实提供相同 TCP 导出协议才能在线预览，普通接收服务不会自动具备该功能。

3D：三个轴和逐通道间距



轴 / 操作含义
Time (sample bucket)时间方向显示采样桶 0--511；未核对采样频率时不直接标为 ns。
Amplitude (ΔADC / ADC)默认 Align baselines 减去各通道中位数基线，零参考等距；取消后显示绝对 ADC。共用幅度尺度，原始值保留。
Channel number纵深轴，标注实际选中通道号；通道之间独立，不插值成曲面。
拖动 / 滚动左键拖动调纵深角度；普通滚轮滚动多通道图；Ctrl+滚轮调通道间距；双击重置。


图示为 8 通道不同基线的合成脉冲，开启基线对齐，仅演示显示效果，不是实板采集结果。
白色背景、浅色参考底面、独立彩色曲线；曲线下方不填充，也无白色遮挡描边。通道多时绘图区域可滚动，不把 68 条线强压在一屏。离线工具打开不再锁死 Run start；避免修改正在采集的文件。

8 MCP 设置与常见排错

MCP 是独立 stdio 工具，复用已保存的 GUI YAML；不重新配一遍 IP。

配置 MCP 客户端

复制安装包 share/config/ecc-control-mcp.example.json，保存为 mcp.json，填写： 
{
  "schema": 2,
  "run_config": "/absolute/path/to/envoy.yml",
  "allow_control": false,
  "request_timeout_ms": 30000
}
MCP 客户端 command 设为安装目录 bin/getdaq-control-mcp 的绝对路径， args 为 ["--config", "/absolute/path/to/mcp.json"]。macOS 位于 GetDAQ.app/Contents/MacOS/getdaq-control-mcp。

MCP 能做什么

ecc_configuration 显示节点和目录；ecc_status 查询实际 ECC； ecc_receivers 查询 Sentry；ecc_operation 查询命令回执。 默认只读。控制需在本地设置 allow_control=true 并重启 MCP，然后调用 ecc_submit_operation，每次指定 node_id、command、唯一 operation_id 和确认文字： 
{"node_id":0,"command":"stop","operation_id":"stop-001",
 "confirmation":"I_CONFIRM_stop_stop-001"}
命令确认只代表 SOAP 已应答，仍要用状态查询确认 Ready / Running。 超时或中断为 unknown，同 ID 重试只读回执，不再发命令。关闭 MCP 不停止硬件。 多节点完整 Run / 归档仍由 GUI 管理；不要同时从 GUI 和 MCP 操作同一块板卡。 旧原生 HTTP 的 base_url / epoch 配置不再适用。详见 docs/MCP_SETUP.md。

排错速查



现象先查什么
Connection refused对应电脑 IP、服务端口、后台是否真实监听；别混用 SOAP / 数据 / export 端口。
Node authentication required (401)节点管理凭据失效。启动会检查本机配对并恢复当前项目凭据；远端从机需重新配对并 Add slave 更新原条目，不必删除板卡组。
Prepare timed out可能远端已执行。先查询状态和 ECC log，不因超时自动重复发命令。
Unknown当前没有可信状态；重启 GUI 不等于复位。核对服务输出、地址和连接。
无数据率 / 无波形确认实际项目目录文件增长；再查 Sentry 监控目录、Data IP、数据端口及 export 端口。
缺少配置文件核对源目录、同步目标、文件 ID 和原版 ECC 的仓库 / NFS。Prepare 匹配 configure-ID。
记录或 catalog 警告确认 ECC Ready 后可手动下一次；保留原数据和未知回执，不直接重复归档。


依据当前源码与配置 / 在线波形 / MCP 说明整理。软件回归不能替代实板接线、数据质量和原生 macOS 验收。

9 按钮速查：入口与主界面

按界面英文原名查找。先分清配置、后台、硬件命令和运行记录。

Run setup 与菜单入口

界面文字含义、使用时机与实际影响
Open YAML读取 GetDAQ 连接与运行设置（YAML），填入节点、IP、端口、路径和实验名。它不是打开板卡 XML 的按钮。

10 按钮速查：采集与自动运行

这些按钮会操作硬件或本次 Run；不要和后台进程的 Start / Stop 混淆。

Acquisition controls

界面文字含义、使用时机与实际影响
Connect按当前节点表连接 ECC，开始查询真实状态与接收监控；受管配置可先检查后台。连接本身不执行 Describe / Prepare / Configure。
Disconnect断开 GUI 的控制/观察会话。仍有工作或采集时按提示确认；远端后台与硬件状态保留。
Progress all对所有节点推进一个初始化阶段，依次 Idle → Described → Prepared → Ready；重复到 Ready。会发送对应硬件命令。
Regress all对所有节点退回一个初始化阶段，执行相应 Undo / Breakup。不是关闭后台服务。
Progress selected node只推进下方选择框中的一个节点；先选对节点。
Regress selected node只让选择框中的一个节点退回一个初始化阶段。
Run start开始本次采集并建立运行记录；若已观察到 Running，则附着观察。已有同号记录或接收文件时按确认提示处理。
Run stop请求停止采集；ECC 确认 Ready 后处理归档、备份和本地记录。服务进程仍运行。
Retry finalization重试可恢复的本地记录收尾；不等于再发送 Stop，也不直接重放结果不确定的 catalog。
Recover journal读取已有运行日志 journal，恢复中断后的记录处理；不会凭空认定硬件已经停止。
Resume failed catalog replacement仅特定同号替换失败、仍在原会话且检查通过时出现。继续原替换流程；普通归档警告不使用它。

Automatic Run

界面文字含义、使用时机与实际影响
Enable / Time / File sizeEnable 启用规则；Time 设置时长阈值；File size 设置接收数据量阈值。两项都选时，先到阈值者触发。
Stop / Next Run阈值达到后，Stop 只停止本次；Next Run 在成功收尾、确认 Ready 后进入下一次。
Runs / Unlimited自动序列总次数，包含第一次；0 显示 Unlimited。
Apply在 Run start 前应用自动运行规则。仅修改输入还没有应用；手动 Run stop 取消自动续跑。
日常顺序：Connect → Progress 至 Ready → Run start → Run stop。需要关闭 ECC / 接收进程，再进入服务管理使用 Stop，而不是只 Disconnect。

Catalog timeout (server normally waits 30 s)等待 Sentry 归档响应的上限；服务器归档自身可能等待约 30 秒。
Transition deadline一次硬件转换及状态确认的等待时限；超时后可能远端已经执行，应先查状态。
Post-stop settling time硬件停止后等待接收数据落稳的间隔，再进入收尾处理。

四个目录分别放什么

界面文字含义、使用时机与实际影响
Configuration source folder (master)你用配置编辑器修改的完整实验配置；这是复制源。
Project data folder执行主机工作目录：ECC 配置副本、接收原始 .graw、Sentry 归档实验/run 子目录。
Configuration cache软件管理缓存、版本和部署回执；收到文件后再同步到工作目录。
GUI Run records root当前 GUI 的 run.yml、journal、CSV 与配置备份；与原始数据目录独立。
修改 Nodes 并 Save and apply 不会立即传 XML。修改 XML 后手动 Sync，或在勾选同步时 Start project services。文件传完后，板卡仍需对应 Configure 命令才会加载新参数。外部未托管 ECC 继续使用原 NFS/仓库。

界面文字含义、使用时机与实际影响
Event log / ECC log / Data log切换当前日志类别；数据日志按实例显示 DataExporter/DataRouter，右侧选择主机/实例或共享 Sentry。
