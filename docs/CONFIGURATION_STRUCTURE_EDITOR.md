# 配置结构编辑：新增、复制、排序和有效子树展开

在原十项及本地引用/改地址/导入之外，新增第14项继承对象浅层覆盖。按对象查询路径补空层级及所需模板兄弟，审阅所有被本地化的具体投影，有效值/对象摘要必须保持；详细例子和include共享来源边界见[对象覆盖手册](CONFIGURATION_OBJECT_OVERRIDE.md)。

当前十种结构保存已与参数/实例覆盖共用会话历史，可预览并撤销/重做完整文件字节，操作和来源守卫见[撤销手册](CONFIGURATION_UNDO_REDO.md)。历史不回滚硬件，不替代跨文件迁移或所有旧命令。

本功能在本机`.xcfg`编辑窗口中使用，延续MUSIC风格的Qt界面与C++11模型。它不向硬件发送命令，不参与原始DAQ数据传输。目标GUI为Qt5.14.2/MinGW，当前验证环境为Ubuntu20.04.6、Qt5.12.8；Windows和Ubuntu24.04实际运行仍待验收。

## 1. 参数值编辑与结构编辑的区别

原来的“Save selected declaration”修改现有参数值，“Preview instance override”给已存在实例生成单值覆盖。结构编辑可以增加对象和参数、删除来源声明、修改名称或ID、复制整段声明、调整同父对象内的顺序，并将一个具体对象当前继承/include所得的有效子树写到本地。

例如，`Board[0]`是一个对象，`gain`是它下面的标量参数。新增`Board[1]`改变实验中可见的实例集合；新增`gain`改变参数集合；改ID会改变引用路径。它们都需要重新审阅完整配置，再生成工件，而不是直接把界面里能保存理解为板卡已配置。

## 2. 从哪里打开

1. 在未连接设备时打开GET配置窗口，选择主`.xcfg`文件。连接模式保留查看和快照功能，结构编辑按钮禁用。
2. 在配置树里选择真正的XML声明，例如`Board[0]`。文件分组标题不是XML声明，不能编辑。
3. 点击 **Edit selected declaration structure...**。窗口顶端给出选中的来源文件和声明路径。
4. 选择操作，填写启用的输入项，点击 **Preview change**。这一步不写文件。
5. 先看 **Change summary**，再按需查看 **Full review record**、**Original XML** 和 **Proposed XML**。
6. 确认全部已加载实例的变化符合意图后，点击 **Apply reviewed change**。程序重新检查来源与预览，成功后重载主配置、核对实际结果，并返回配置树。

修改任一输入会禁用旧Apply。主配置重新打开或重载后，旧对话框的版本门槛会拒绝保存；请关闭旧对话框、重新选中声明。来源文件被外部编辑后也必须重新打开和预览。

## 3. 原有十种操作分别做什么

| 操作 | 应选择的声明 | 需要填写 | 结果 |
| --- | --- | --- | --- |
| Add child object | 一个对象 | 新元素名、可选ID | 在该来源对象内追加空子对象 |
| Add child scalar | 一个对象 | 新元素名、可选ID、类型、值；可选单位/范围 | 追加有明确类型的参数 |
| Delete selected declaration | 非根对象或参数 | 无 | 删除所选完整XML元素；其他文本保持 |
| Change selected ID | 非根声明 | 新ID；空表示移除ID属性 | 改变具体路径或默认声明身份 |
| Materialize current effective children | 主文件中的具体对象 | 无 | 展开当前有效子树，要求整棵配置的有效参数/对象完全不变 |
| Change selected element name | 非根声明 | 新元素名 | 同步修改开始/结束标签，保留内部内容和其他属性 |
| Clone selected declaration | 非根声明 | 可选新名称、新ID | 深复制完整XML子树，追加到同一父对象 |
| Move before sibling | 非根声明 | 同一父对象中的另一个来源声明 | 把完整元素移到该兄弟元素之前 |
| Move after sibling | 非根声明 | 同一父对象中的另一个来源声明 | 把完整元素移到该兄弟元素之后 |
| Edit scalar type/unit/range | 一个参数声明 | 类型、单位、范围；空属性表示删除该来源属性 | 保留原值、CDATA/注释和其他属性，审阅全部共享影响 |

新增/改名使用普通XML名称，例如`Board`、`gain`、`readoutDepth`，不是带`/`的配置路径。ID不带外层方括号，例如填`1`，界面显示为`Board[1]`；`*`是默认声明，可能影响多个实例。新标量类型可选`int`、`hex`、`real`、`bool`、`string`，空字符串须选择`string`，保留标量角色。

修改现有参数属性时，单位/范围输入先显示该来源的原声明；清空表示删除这处声明，不保证整个共享类变成无单位/无范围，因为别处的声明可能接替。类型可以选择Auto type移除显式type，让现有文本按原语法自动推断；空标量必须保留显式类型。新增参数仍要求明确类型。该操作只改属性，原值文本、CDATA及行内注释保留。

不能删除、改名、改ID、复制或移动文档根；根可以新增子元素或展开有效子树。复制后名称与ID不能和现有同父声明冲突。排序仅针对同一来源父对象中的兄弟元素，不跨文件搬移。来源中选中的是include文件的声明时，普通结构操作编辑该include来源本身；窗口会显示文件名，它可能影响多个已加载投影。

新增本地文件引用、修改/移除引用和导入三个操作，保留原操作编号和会话历史。逐步用法及来源守卫见[引用与导入手册](CONFIGURATION_INCLUDE_IMPORT.md)。

## 4. 为什么新增和排序也可能改变其他板卡

旧CompoundConfig按元素名路径共享单位和范围，忽略ID；最后一个非空单位声明可能覆盖同类此前单位。例如：

```xml
<Setup>
  <Board id="0"><gain unit="V">2</gain></Board>
  <Board id="1"><gain unit="mV">3</gain></Board>
</Setup>
```

两块Board的gain共享同一单位。按当前顺序，单位为mV；把Board[1]移到Board[0]之前后，最后的V会作用于两者。值2和3不会自动换算。因此预览必须显示两处单位变化，不能只显示被移动的那一行。

新增标量时填写单位/范围同样属于共享声明。候选树会检查所有已加载标量的类型与共享范围，包含尚无具体实例的默认声明；任一值变得非法就拒绝预览。重复元素、include直接导入碰撞和隐藏模板中的重复声明也拒绝。

预览只涵盖当前已加载的主文件和include集合。编辑一个被其他工程引用的公共文件，不能据此证明那些未加载工程也合法；保存前应确认该来源的使用范围。

## 5. “展开当前有效子树”是什么意思

考虑以下默认配置：

```xml
<Setup>
  <Board id="*"><Module><gain range="[0,10]">2</gain></Module></Board>
  <Board id="0" extra="keep"/>
  <Board id="1"/>
</Setup>
```

选中主文件里的Board[0]展开后，程序将它当前可见的Module/gain写到该对象内，保留`extra="keep"`、原有注释与本地子元素。Board[1]和默认模板保留原字节。当前全部有效参数、类型、单位、范围和具体对象集合必须和展开前一致；来源位置和文件摘要会变化，所以预览显示`effective_changed:false`、`snapshot_changed:true`。

若所选对象有include，程序将当前可见内容写入本地，并移除该物化对象的include属性，保留原include文件。嵌套的已存在本地对象也逐层处理，借入的标量保留有效类型、单位/范围及其他已识别属性；空对象和有明确type的空字符串也保留。属性处理按XML引号边界扫描，不能误删其他属性值中的`id=`或`include=`文字。

这是一份**当前已存在有效子树的展开**。它不凭空生成默认`*`对应的所有未来实例，不删除未选中的模板，也不保证以后共享单位、范围或默认模板变动不会影响配置。它不是硬件部署、独立运行快照或整个旧库的完整序列化替代。不能直接选include来源或带`[*]`路径做这项操作；请先选择主文件中的具体声明。遇到XML命名空间或复杂共享投影无法证明等价时，会在重新解析/比较阶段拒绝，而不是静默改语义。

## 6. 保存时检查什么

`XcfgStructureEditor`保存原请求、原文件字节、候选文件字节、前后有效快照和完整差异报告。Apply重新生成候选；上述字段任一不符，都要求重新预览。所有已加载来源在计算前后、保存前都按原字节检查。

候选在内存中通过原`XcfgDocument`解析，不临时改动include磁盘文件。普通公开快照捕获仍核对实际磁盘来源；仅结构编辑内部、在原来源已核对后，才能对虚拟候选复用同一快照算法。没有复制一套不同的参数摘要规则，也没有放宽原快照验证。

实际写入使用`QSaveFile`替换一个来源文件，之后重载并重新捕获实际快照，与审阅的候选快照核对。若文件已保存但重载或结果核对失败，错误明确包含 **Structural edit saved, but ...**；不能把它解释为“什么都没写”。此时模型清空，必须重新打开并调查实际文件。程序不自动回滚、删除来源或重发硬件命令。

这是单文件替换，不是跨进程/跨文件锁、目录fsync或断电恢复保证。它无法阻止另一个进程在检查后继续修改文件；真实加载版本仍须在ECC/板端另行核对。

## 7. 大小限制与文件保护

继续使用原文档预算：单来源8MiB、所有来源64MiB、最多256文件、include深度32、XML深度128、100000来源节点和有界有效树/子项索引。结构候选和展开过程中也检查生成大小和节点预算，不无界扩展默认实例。

未编辑的XML文本、未知字段、注释和include文件保留。删除是对选中元素的明确删除，复制保留其完整子树；移动只移动元素本体，旁边的独立注释不会被擅自解释为“属于这个对象”并一起移动。选择的来源声明有多个使用者时，差异表会列出当前已加载的影响。

本阶段测试仅生成小型临时XML/JSON并自动清理，没有传输原始DAQ数据；工作区每轮传输测试合计最多20GiB且结束删除的约束继续有效。
