# GET 配置文件页面

入口：主窗口顶部 **GET configuration files...**。这部分使用 Qt Core/Widgets，属于低频配置与检查功能，不读取原始采集流，也不会写硬件寄存器。

## 当前可用功能

新增 **Review source workspace copy...**，复制主XML及所有加载include到新目录，保留引用或按每次使用拆分，以便隔离编辑。预览映射、改为内部相对路径、整体有效摘要一致、不覆盖目录和另存后打开已接；详见[工作区副本手册](CONFIGURATION_WORKSPACE_COPY.md)。

新增 **Review XML export / Save As...**，可导出选定对象或整文件的自包含XML，保留默认声明或固定当前具体有效值，并可明确打开新副本；先预览、来源守卫和不覆盖创建。逐步操作及与快照/发布区别见[XML导出手册](CONFIGURATION_XML_EXPORT.md)，旧命令对应与未完成范围见[迁移表](CONFIGURATION_COMMAND_MIGRATION.md)。

已增加 **Edit selected declaration structure...**：新增对象/参数、删除、改ID/名称、复制、同父排序、修改类型/单位/范围，以及展开主文件中的当前有效子树。先看完整差异与拟写XML，再Apply；连接期间禁用，不发送硬件命令。详细例子、十种操作和失败说明见[配置结构编辑](CONFIGURATION_STRUCTURE_EDITOR.md)。

打开本地 UTF-8 `.xcfg` 或 `.xml` 后，程序读取它引用的本地 include 文件；树按真实来源文件分组，显示元素、ID、文件中的声明值、声明单位、声明范围及行号。文件名和完整元素路径可在提示中查看。

这里的 **Declared value/unit/range** 指来源声明解析后的内容。普通XML文本中的排版空白按旧TinyXml语义折叠，CDATA/字符引用中的明确空白保留；原文件准确字节另行保存。字符串编辑把输入空白编码为字符引用，保证重载/范围检查/撤销结果准确，例子见[旧库运行对照与文本迁移](LEGACY_CONFIGURATION_RUNTIME.md)。查询一个具体scalar时，现在会另列共享类的有效单位、范围及各自来源；不会把这些内容反写到声明树。某个实例没有写unit/range，仍可能受到其他同类声明的约束。

源码模型在 `common/config/xcfgdocument.*`，窗口在 `apps/envoy/configwindow.*`。没有引入 TinyXML、Boost、数据库或新的第三方 XML 库，使用现有 Qt Core 的 QXmlStreamReader。

## 查找某个值来自哪里

在查找框输入从根开始的路径，例如：

```text
Setup/Node[CoBo]/Instance[0]/Module/readoutDepth
```

点击 **Find value source**。程序给出找到的值、原始文件、行号和声明路径；scalar还显示Shared class、Effective unit/range和Unit/Range source。值、单位和范围可以来自三个不同声明。根元素有 ID 时，可写完整根路径，也可只写根标签名。

查找按旧实现的回溯顺序处理具体 ID 和 `id="*"`；不会因为存在默认对象就凭空认为任意板卡 ID 都存在。include 导入的是被引用文档根对象的内容，而不是额外套一层根标签。重复声明/包含冲突会报错，不任意选择其中一个。

一个不直观但重要的例子：多层默认对象中，尚未在查找路径上找到具体实例时，不能提前把该层默认对象当作实例。旧源码 `CConfigTest::testSearchNestedBack3` 的 x 值来自更远的声明 4.5，而不是看似更近的默认值 0；新测试保留了这个结果。这仍不是全部旧 CompoundConfig 语义已验收的证明。

## 修改一个声明值

1. 先 Disconnect，打开配置页面；连接状态下页面只读。
2. 打开实验配置，找到真正需要修改的**来源文件里的声明**。
3. 选中一个已有文本的 scalar，例如 `<gain range="[0,100]">20</gain>`。
4. 在下方输入框填新值，点击 **Save selected declaration**。
5. 程序检查声明类型及其所有投影上下文的共享范围，核对整个已加载来源集合没有变化，再原子保存选中文件。
6. 保存后重新读取主文件及 include。没有发送 ECC 命令，没有上传远端文件；部署和后端有效配置校验另行进行。

配置树的参数值列可双击或在该单元格按F2直接行内编辑；枚举/布尔值用下拉框，整数区间用微调框。下方单行框适合短值，**Edit value...** 适合多行值。选择对象时不会伪装成可编辑参数，页面会提示选择其下的scalar；双击对象名称可直接打开结构编辑，以新增/删除参数。按 **Find value source** 查找时会同步选中并滚动到实际来源声明，随后即可编辑。保存及其有效配置前后快照在后台执行，窗口显示进度，完成后刷新；多行输入以LF保存，若原值含回车，保存前会明确询问是否规范化行尾。

修改 `id="*"` 下的值会改变默认模板：具体实例中没有单独值声明的会继承新值，已有显式值保持不变。保存前会列出这一影响并要求确认；大配置的前后快照在后台计算。需要单实例调整时使用下节的覆盖预览。

## 为已有实例创建覆盖

例如默认Board的Module/gain为2，Board[0]和Board[1]都是已声明的具体实例。你希望只有Board[0]变为4：

1. Disconnect后打开配置页面，在查找框输入Setup/Board[0]/Module/gain，先Find value source核对当前值、共享范围和来源。
2. 在**Value for the concrete lookup path only**输入4，点击**Preview instance override**。
3. 状态显示目标路径、实际要改的文件、原值和新值；下方只读XML框显示完整候选文件。此时没有写磁盘，也没有发送硬件命令。
4. 核对候选新增Board[0]下的Module/gain，而默认模板和Board[1]保留。点击**Apply previewed override**才保存。
5. 输入路径或覆盖值改变会撤销当前预览；应用前重新生成候选并核对字节及所有来源。原文件在预览后被外部修改时拒绝，不覆盖它。

路径中的实例必须已经能通过原Lookup确认，不能凭空创建Board[99]或用'*'覆盖全类。覆盖只生成该路径缺少的结构与一个显式type的scalar，保留其余属性/注释；自闭合本地对象可扩为带子元素的对象。原scalar若直接位于当前本地路径，使用Save selected declaration编辑，不再添加重复项。

覆盖不复制共享unit/range，继续受原类约束。程序在内存中解析候选，枚举前后有效scalar：集合相同、其他值/type及所有共享属性不变，目标须解析到拟写入文件的新值，才允许应用。因此复杂回溯中会影响其他值的结构不自动保存；需要人工审阅整体配置。

include不是可随意覆盖的字典。若当前对象的include已经直接导入同名同ID元素，再在本地添加它会形成旧解析器禁止的碰撞；预览拒绝并保留文件。应调整明确的结构边界，不能删include内容或把整棵树展开反写来绕过。打开include作为主文件只核对当前已加载树，不能证明其他未加载工程不引用它。

连接期间覆盖输入、预览和应用均禁用。GUI重开、Open新文件或成功编辑后撤销旧预览；预览不是持久化部署工件。保存仍只是本机单文件原子替换，检查不是跨文件写锁或断电恢复保证；保存后重载失败会明确报告Override saved, but reload failed，不能当作从未写入。

保存采用最小文本替换：除选中值的文本以外，其余原字节不重新格式化。保留中文、空白、注释、未知属性、其他节点及 include 引用；引用文件各自独立，不把整棵展开树写成一个文件。

一个有效值片段前后的行内注释、处理指令和CDATA现在可以保留后修改。只替换选中值片段，其余标记和XML排版空白不重排；CDATA能表示新值时保留原形式，遇到 `]]>` 或回车改为一个字符引用文本片段，保证准确值而不拆成多个文本节点。自闭合空值仍不在表格中修改；分裂为多个有效文本片段的旧XML仍严格拒绝，不能把支持首尾注释理解为任意混合文本都等价。读到未知字段可以展示并保留，但不因此声称旧后端一定接受该字段。

## 类型和范围

支持显式 `type="int|hex|real|bool|string"`。未声明type时，编辑器按原文本的自动类型保持编辑类型；范围内每个字面量独立按语法确定类型。布尔文本大小写可识别，编译输出规范为true/false；实数必须有限，采用固定C locale解析。

支持枚举、数值/字符串/布尔区间、开区间及-inf/+inf。开区间使用旧CompoundConfig方括号方向。枚举按集合比较，顺序和重复项不改变含义；{}为空集合，{""}包含一个空字符串。双引号字符串支持逗号、空格、引号和C转义（常用控制字符、反斜线、八进制和单字节十六进制）；带空格的枚举字符串必须加双引号，单引号不是字符串分隔符。

int为有符号64位，hex为无符号64位，比较不经double。例如9007199254740993不会与9007199254740992混同。收到的旧库Int/Hex是32位，64位是新软件的明确扩展，不能据此保证旧后端接受更宽配置。real使用有限double；string按字节词法顺序比较；单位仍不自动换算。

| 范围与值 | 是否接受 | 原因 |
| --- | --- | --- |
| [0,10]与int 5 | 是 | 整数域和闭区间 |
| [0,10]与real 5.0 | 否 | 比较域不同，不隐式转成整数 |
| [0x0,0xff]与hex 0x10 | 是 | 十六进制域 |
| [0,255]与hex 0x10 | 否 | 必须把范围也改成hex边界 |
| {"a,b","a\\\"b"}与string a,b | 是 | 引号内逗号是字符串内容 |
| ]-inf,+inf[与任何类型 | 是 | 两端无界，忽略端点方向，遵循旧contains逻辑 |

枚举内类型必须一致。有限区间端点与值也须同类型；混合类型端点不会通过隐式转换扩大接受范围。范围语法必须完整消费，尾部垃圾、坏转义、溢出、非法分隔符或NaN/Inf实数拒绝。范围/值最大1 MiB UTF-8字节，最多4096项；超限不编辑。

## 共享类怎样形成

收到的CompoundConfig源码用getClassPath/createGenericPath把路径上所有ID替换为通配；ScalarClassInfo只共享unit/range，不共享值或type。例如Setup/Board[0]/gain与Setup/Board[1]/gain[2]都属于Setup/Board/gain类。参数名other或父元素名Other不同，则属于另一类。

```xml
<Setup>
  <Board id="*"><gain unit="V" range="[0,10]">2</gain></Board>
  <Board id="0"><gain>4</gain></Board>
  <Board id="1"><gain unit="mV">6</gain></Board>
</Setup>
```

这里最后一个非空unit声明把整类单位改成mV；range仍来自默认Board的gain。Board[0]的值仍是4，程序不会把它换算成4000；共享单位改变与数值换算是两件事。编辑Board[0]为11会因共享范围拒绝，即使该行没有直接写range。

解析按旧XML入口顺序：进入对象时先独立载入include、导入其根的内容，再处理本地子元素。include导入携带已形成的类信息；加入现有类时必须兼容，不能把它当作最后出现的本地setUnit。共享类成员一方没有unit/range时，可以接收另一方已有的类信息；这既适用于无属性的导入成员加入已有类，也适用于导入属性补齐此前遇到的本地无属性成员。只有双方都带类信息而单位或范围不兼容时才报冲突。原始include文件不被展开改写。用“Find value source”查询具体scalar时会显示继承后的有效单位、范围及其声明来源；树表本身仍显示每个文件中实际写下的属性。

同一include在A和B两种父路径使用时，会形成两个不同的投影类。编辑该来源里的值会影响两处，因此必须满足两处的范围；任一处不满足都不保存。查询与编辑器保留来源文件/行号，不把投影路径冒充实际文件路径。

导入范围现在按解析后的语义比较。[0,10]与[0, 010]相同；{1,2,1}与{2,1}相同；0xFF与0xff也相同。[0,10]与[0.0,10.0]类型不同，仍冲突。单位必须一致，不做物理单位换算；空的未声明范围与明确{}不同。实际旧库函数体的比较范围及仍未运行的Spirit解析器见[验证记录](VALIDATION.md)。

配置编译入口ExperimentReader也使用共享元数据。参数追溯中的attributes表示有效属性；涉及其他声明时增加shared_metadata，分别记录unit/range的来源，不改变具体值来源。部署仍须走固定工件/摘要核对，不会从配置页面直接写硬件。

## 读取限制与报错

每文件最大 8 MiB，全部来源最大 64 MiB，最多 256 个来源文件，include 深度最多 32 层，XML 深度最多 128 层、节点最多 100000 个。查找还有分支数量上限。共享投影最多200000次访问，路径最多128层/65536 UTF-8字节，累计投影路径最多64 MiB；超限保持原文件，不生成不完整的有效属性。

只解析本地文件 include，支持相对路径、绝对路径和 file URL；不连接数据库或从 HTTP 下载引用。检测循环引用和缺失文件。拒绝 DTD/自定义实体声明。非 UTF-8 文件先保留原件，在明确编码后转换，不能让编辑器猜编码再保存。

“Source changed since loading”表示某个已加载来源在加载后被改动，包括提供共享范围的其他文件；重新打开后再修改，不使用旧约束写另一文件。保存前的全来源检查不是跨文件写锁，外部程序仍可能随后修改include。保存成功后若重载失败，错误明确说“Value saved, but reload failed”，应核对磁盘文件，不能理解成从未写入。

## 保留CDATA和首尾标记修改值

1. 断开控制连接，打开配置文件，在声明树选中已有scalar。只读窗口不允许保存。
2. 检查来源文件、当前值、类型及共享范围。例如 `<n type="int" range="[0,9]"><!-- keep --><![CDATA[2]]></n>` 的值是2，注释不是值。
3. 在ConfigValue输入3，点击 **Save selected declaration**。结果仍是 `<!-- keep --><![CDATA[3]]>`，原属性、外层注释、其他节点和include保持原字节，不发送硬件命令。
4. Undo仍需审阅准确旧/新来源与有效差异再Apply；恢复的是原始字节，包含原CDATA/注释。Redo同样审阅，不只是重新设置数值。
5. 范围不符、任一加载来源变化或未完成Save All标记会拒绝，先重开核对，不自动覆盖外部修改。

CDATA不能直接包含终止符 `]]>`；不同XML读者也会处理字面回车。因此这类输入会转为一个普通文本片段，使用 `&gt;`、`&#13;`、`&#10;`、`&#32;` 等保存准确值，首尾注释/处理指令不改。这是表示形式变化，不能要求CDATA外壳同时保持。NBSP是值的一部分，不能当成可丢弃的XML排版空白；空字符串若无type会变成对象，仍拒绝。

值列支持直接行内编辑：双击值单元格或选中后按F2；枚举和布尔值显示下拉框，带边界的整数按范围显示微调框，其他类型用文本输入并在保存时执行配置校验。多行值仍可通过 **Edit value...** 打开大尺寸编辑器；该编辑器按Qt纯文本行语义保存为LF，原值含CR/CRLF时会先提示。`a<!-- comment -->b`等多个有效文本片段仍拒绝加载，避免沿用旧访问器丢掉前半值的行为。旧版多选上下文菜单只提供复制、剪切和删除，不提供批量改值；当前界面也不将多选编辑伪装成已有能力。

旧 `.bcfg` 配置可通过 **Review legacy binary configuration conversion...** 先审阅再转换到新的XML，也可导出旧版本1二进制；原文件和硬件保持原状。完整步骤、32位兼容限制和失败处理见[二进制配置手册](CONFIGURATION_BINARY_FORMAT.md)。
