# 配置文件的引用、替换引用和导入

配置树中有两个容易混淆的动作：**引用**保留与外部文件的关系；**导入**把当前外部内容复制到选中的本地对象。它们只编辑本机配置，不运行ECC命令，不参与DAQ原始数据传输。

本轮在现有结构审阅窗口增加三个操作，并继续使用原来的保存、完整差异和会话撤销/重做机制。目标是补齐旧ConfigWidgets的IncludeConfig、SetConfigNodeIncludeUrl、ImportConfig常用本地文件用法；不是声称全部CompoundConfig、数据库或网络资源都已兼容。

## 1. 三个操作怎样选择

| 窗口选项 | 对现有子内容的处理 | 保存后是否依赖外部文件 |
| --- | --- | --- |
| Replace children with local include | 删除所选对象内的原子内容，改为引用目标文件根的内容 | 是 |
| Change/remove local include path | 保留本地子声明，修改引用；路径留空表示移除引用 | 有路径时是，移除后否 |
| Import local configuration children | 删除原子内容，把目标文件的当前内容展开到本地，并移除所选对象的include | 否；撤销历史仍核对本次导入来源 |

引用和导入都保留选中对象自身的元素名、ID和其他属性。外部文件的根标签不会额外嵌套到这个对象中。例如引用 `<Template><gain>…</gain></Template>` 到 `Board[0]`，会得到 `Board[0]/gain`，不是 `Board[0]/Template/gain`。

“替换”会明确丢弃原对象内部的子元素及内部注释；外部文件、本对象外的注释及文本保持。请先看Original XML和Proposed XML确认删除范围。“修改引用地址”保留本地子元素，但新引用若与本地元素重名/同ID冲突，会拒绝预览。

## 2. 操作步骤

1. 在未连接硬件的配置编辑窗口打开主`.xcfg`。
2. 从配置树选择真正的对象声明，例如`Board[0]`。不要选参数或文件分组标题。
3. 打开 **Edit selected declaration structure...**。
4. 从Operation选择上述动作。
5. 在Include/import file输入本地路径。相对路径按**选中声明所在来源文件的目录**解释，不按主配置目录或程序启动目录解释。
6. 点击Preview change，此时没有文件写入。
7. 检查Change summary中的全部参数、对象变化；共享声明可能影响不止一个实例。
8. 检查Input dependencies中的文件路径、字节数和摘要。导入后不再属于有效include树的文件，也会列在这里。
9. 查看原文、拟保存原文和完整审阅记录。确定原子内容被替换或保留的方式符合预期。
10. 点击Apply reviewed change。保存前会重新读取并比较所有审阅来源，成功后重载并核对有效树。
11. 需要恢复时使用Review undo...，先审阅再保存；恢复的是本地XML，不是硬件状态。

修改任何输入会撤销旧Apply。原文或外部文件变化后必须重新预览；不能拿之前的摘要继续保存。连接状态只读门槛和重新打开配置的窗口版本门槛继续有效。

## 3. 引用示例

选中主文件中的对象：

```xml
<Setup>
  <Board id="0"><old type="int">1</old></Board>
</Setup>
```

外部文件`common-board.xcfg`：

```xml
<Template>
  <gain type="int" range="[0,9]">4</gain>
</Template>
```

选择Replace children with local include、输入`common-board.xcfg`后，本地对象保留`Board`和ID，删除`old`并增加include。有效参数为`Setup/Board[0]/gain=4`。以后外部文件改变，会影响重新加载后的有效配置；它不会自动向硬件加载。

如果对象已有本地参数，选择Change/remove local include path可保留本地参数，只改变外部来源。若本地和新引用都声明同名同ID的`gain`，程序明确拒绝，不能用顺序猜谁覆盖谁。留空移除include会丢失通过该引用可见的参数，差异表应显示它们被移除。

## 4. 导入示例及嵌套include

Import local configuration children将外部根的子内容写到本地。嵌套include也按外部文件所在目录展开，不把相对路径直接复制到新目录后再错误解析。

导入保留声明中的默认ID `*`、具体ID、标量值/属性以及可保留的内部注释。默认声明不会被擅自当成实际板卡；保存后仍用同一继承/共享属性模型校验。外部根自身的名称、ID或其他属性不替换本地对象的属性。

保存后主配置的有效来源可以只剩本地文件。导入是一次当前内容复制，不是持续同步；后来修改外部文件不会自动改变已经导入的参数。

## 5. 为什么导入后撤销仍检查原外部文件

预览记录全部引用/导入来源的字节。导入后，外部文件可能已经不在当前配置树中，但本次审阅和历史仍保留它的校验摘要。外部文件即使只改变注释，旧预览也会失效，历史重放也会拒绝。

这样做是为了不把来源已经变化的审阅记录当成当前事实。程序不会恢复或覆盖外部文件；需要继续工作时重新打开配置、按当前文件建立新的审阅。会话历史不是跨文件事务或永久版本仓库。

## 6. 拒绝条件与保存边界

只支持本地文件和本地file URI。HTTP/数据库资源没有新增客户端或依赖。文件不存在、对象根无效、递归引用、声明冲突、类型/共享范围冲突及生成大小超限都拒绝。

保留单文件8MiB、已加载来源64MiB、来源256、include深度32、XML深度128和节点预算；导入展开另有访问与输出预算。只替换一个选中来源文件，不修改导入文件，不跨文件移动声明。

保存前重算预览并核对外部来源，保存后重载和摘要验证；另一个进程仍可能在检查后修改文件，这不是跨进程锁或断电事务。若提示已经保存但重载/核对失败，实际写入可能发生，模型会清空，必须重新打开检查；不能当成什么都没写。

## 7. 依据及验证范围

本地旧源码的IncludeConfig先删除子项再调用Document::include；后者按来源上下文解析资源并保留include URL。ImportConfig同样替换子内容，由Document::import导入内容。新操作按这些职责迁移，使用现有Qt/Core和C++11，不增加SOCI、Spirit或网络库。

模型新增用例覆盖引用/改路径/导入、默认与具体ID、嵌套include、注释/未知属性、准确字节撤销/重做、导入来源变动后旧预览/历史拒绝，以及递归、冲突、缺文件、非对象根和网络地址拒绝。实际界面检查预览不写、输入改变撤下Apply、依赖列表、保存和Undo。

最终普通/新代码ASan/UBSan/LeakSanitizer模型各51、普通完整窗口70、有效快照CLI12及系统实验编译/原生离线绑定36通过，凭据在build-config-includes/checkpoint.json和[验证文档第70.3节](VALIDATION.md)。系统Qt未整体插桩，没有连接实机或运行大流量传输。

未接入的数据库/网络资源、跨文件写入/迁移、旧Spirit全库运行对照、硬件加载和Windows/Ubuntu24/macOS验收仍有独立工作；不能把本轮三个动作当整套重构完成。
